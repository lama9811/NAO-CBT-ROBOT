# Pinned, not >=. `openai-agents>=0.0.5` resolves to 0.22.0, which requires
# openai>=3 -- and litellm (below) still pins openai<3, so the two cannot be
# installed together. A fresh venv built from the loose pin ends up with the
# Claude models silently unavailable ("litellm unavailable, cannot use
# Anthropic model ..." at import) and every agent falling back to OpenAI.
# 0.13.6 is the version this code was developed against.
openai-agents>=0.13.6,<0.18
# Upper-bounded, not pinned. A newer `openai` makes `cache_write_tokens` a
# REQUIRED field on `InputTokensDetails` while openai-agents builds that model
# without it, so every agent turn dies mid-stream on a pydantic
# ValidationError -- and the turn still logs `outcome=ok` with an empty reply,
# so Nao just goes silent and nothing looks broken. Confirmed broken on
# 2.54.0; confirmed good on 2.26.0 (Mac) and 2.36.0 (Pi, in production), which
# are the two endpoints of this range. Bites Claude turns too: LitellmModel
# still normalizes usage through OpenAI's types.
#
# Ranges rather than == on purpose: the Mac runs 2.26.0/0.13.6 and the Pi runs
# 2.36.0/0.17.1, both working. An exact pin would silently downgrade whichever
# machine did not match next time its venv was rebuilt.
openai>=2.26.0,<2.37
